# Loci 规则分层实验

日期：2026-10-07。状态：研究实验，不是产品重构或五客户端验收。

实验使用本机 Ollama `qwen3:14b`，以真实工具调用循环读写合成文件。工具只允许访问本实验的工作区；任务调用仓库现有 `scripts/loci-task.js` 的副本。没有改用户真实大脑、全局指令或模型配置。协议参考 [Ollama 工具调用文档](https://docs.ollama.com/capabilities/tool-calling)。

三组接收同样的宿主说明、工具、用户请求、偏好、配置、索引和模块指南，只有宿主提供的规则内容不同：

- full：此前供审阅的完整 LOCI.md，加共同的按需指南索引，6307 UTF-8 bytes。
- compact：保存触发/模式/边界 + 数据和指南索引，1619 bytes。
- pointer：大脑位置 + 模块名称和路径，700 bytes；保存判断放在按需文件。

所有组均是每案例独立新会话。日期固定为 2026-10-07，时区 Asia/Shanghai；所有人物和项目均为合成。temperature=0、num_ctx=16384、num_predict=1600、最多12轮；固定 seed。实际 prompt token 由 Ollama `prompt_eval_count` 返回；字符/bytes 不冒充 token。时长包括本地请求、模型加载、推理和文件工具，受缓存及执行顺序影响，不能外推其他模型。

分阶段：先做 qwen3:14b 开启推理的任务冒烟，再做 qwen3.5:4b 关闭推理的8案例×3组，以及补强候选 compact-v2 的8案例。观察到漏做步骤后，再用 qwen3.5:4b 开启推理检验候选和关键对照；汇总按模型、think、版本分组，不把不同运行模式混成同一通过率。compact-v2 把路径前缀、保存模式前置条件和结果核对写清，其他合成数据/工具/指南保持一致。

方法修正单列：原 manual 案例是命令式“明天早上九点把季度材料发给客户”，可能被理解为直接创建任务；补充声明式“我明天早上九点要把季度材料发给客户”，称为 manual-statement。原合成项目索引使用 `../work/windbell`，而仓库 `loci-project.js` 实际通过 path.resolve 写绝对 repo/memory 路径；另用 `--absolute-project-index` 重跑相关案例，原结果保留。两种索引环境分组，避免把实验构造的问题归因于现有产品。`summarize.py` 用当前评分器统一复核所有落盘结果（包括路径规范化、字段精确检查），原逐次 JSON 和工具轨迹不改。

8种案例：闲聊、带时间的任务、会议、manual模式、即时称呼偏好、项目最新状态读取、项目技术决定、人物关系。评分以实际文件哈希差异、数据内容、工具轨迹和最终回复为依据，不用另一个模型主观打分。保存案例额外检查活动记录只有一条；项目决定检查是否写在该项目、是否用了指南规定的四部分和字段。补强阶段另查原偏好保留与当前项目记忆更新，原阶段这些案例本已失败，不改变其通过数。没有假设调用工具成功就等于最终正确。12轮仍不能完成属于行为失败；接口空响应或网络异常单列，不当作完成的行为案例。

`run.py` 可复跑；`variants/` 保存三组规则；`results/` 保存完整合成请求、工具轨迹、token计数和评分；`fixtures/` 保存合成文件。运行示例：

```sh
python3 .loci/experiments/2026-10-07-layering/run.py --model qwen3.5:4b --no-think --cases all
```

`preflight-think-false/` 是接口预检：think=false 的3次调用没有内容、没有工具调用，不能计作规则失败或有效行为样本。后续使用 think=true，先用单工具请求验证真实工具调用，再跑对照。

局限：本实验直接向模型提供规则，检验“已收到规则后如何行动”。没有检验 Claude/Codex/WorkBuddy/千问/豆包各自是否自动加载全局文件、是否截断、是否存在额外规则冲突；没有模拟长会话压缩、真实用户噪声、并发写入、全部模块或提醒送达。小样本结果不能变成可靠性百分比承诺。

实验结束后，合成数据与原始日志移入 `.loci/experiments/`，避免进入项目知识库检索。历史工具轨迹保留原始路径；评分器仅规范化历史路径前缀，不改写轨迹或实验结果。
