# 行为评测集

`tests/` 里的其它测试覆盖**确定性写入器**（`loci-task.js` 等）——输入什么，输出一定是什么。

这套覆盖的是另一半：**969 行提示词规则，模型到底遵不遵守。**

## 为什么能自动判分

因为路由规则有唯一正确答案：「明天九点发材料」必须进 `tasks.json` 且不进 `calendar.json`。
所以一条样本 = 一个干净大脑 + 一句话 + 一次文件系统 diff，**不需要 LLM judge**。

这是架构选择的直接结果：选了规则驱动而不是让模型自由发挥，系统才有「对错」可言。

## 跑

```bash
node tests/eval/run.js                  # 全部
node tests/eval/run.js --case manual-mode-respected
node tests/eval/run.js --dry-run        # 只搭夹具，不调模型（验证 harness 本身）
node tests/eval/run.js --keep           # 保留临时大脑，便于事后翻现场
```

每条样本会 rsync 一份仓库当临时大脑（约 4 MB），用 `CLAUDE_CONFIG_DIR` 隔离掉全局
`~/.claude/CLAUDE.md`，避免模型跑去写你真实的大脑。跑完删除，`--keep` 可保留。
结果落在 `tests/eval/last-run.json`。

## 加样本

编辑 `cases.json`：

```json
{
  "id": "短横线命名",
  "why": "这条在防哪条规则被改坏",
  "config": { "persistence.mode": "auto" },
  "prompt": "用户说的一句话",
  "expect": {
    "writes":      ["必须写的路径"],
    "writesAnyOf": ["这几个里至少写一个"],
    "notWrites":   ["不准写的路径"],
    "replyMatches": "回复里必须出现的字"
  }
}
```

`"writes": []` = 这条是**负样本**，正确行为是什么都不写（噪音率指标）。

## 指标

- **路由准确率** — 该写的写了，且写对了文件
- **噪音率** — 不该写的时候写了（负样本）
- **即时生效** — 偏好类规则，确认那句回复本身就得遵守（`replyMatches`）

## 语料原则

**只用合成语料，不放任何真实个人信息。** 这套评测测的是路由，不是内容，
合成数据完全够用——而且这样它可以随产品一起开源。

## ⚠️ 一条用血换的教训：评测本身会骗你

**第一次跑就踩了。**

harness 当时用 `CLAUDE_CONFIG_DIR` 隔离全局 `CLAUDE.md`，顺手把登录凭证也隔离了。
`claude` 根本没启动，输出是 `Not logged in · Please run /login`，**一个文件都没写**。

而那条样本期望的恰恰是「什么都不写」——

```
跑 manual-mode-respected ... pass (1s)
    写入: (无)
1 / 1 通过
```

**「系统没跑起来」被判成了「系统完美」。**

唯一露馅的地方是 `1s`——一次真实会话不可能一秒跑完。如果当时没多看一眼耗时，
这条假阳性会一直躺在通过率里，而且越积越多。

### 所以

**ERROR ≠ FAIL，必须分开：**

- **ERROR** = 评测自己坏了（没登录、超时、进程没起来、输出为空）→ **不计入通过率**
- **FAIL** = 评测正常跑了，产品行为错了 → 这才是真信号

`sanity()` 就是干这个的：每条样本在判分前先验证它真的到达了模型。
没有这道关，任何「期望不写入」的负样本都会把系统故障洗成满分。

**推论：一个只会报通过率的评测是危险的。** 它必须同时报「有几条根本没跑成」。
