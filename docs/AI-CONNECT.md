# 给 AI 的 Loci 接入指南

用户已在这台电脑使用 Loci，现在要求把**当前与你对话的客户端**接到同一大脑。由你查找、配置并验证，不让用户去旧 Agent 查询路径、填路径占位符、编辑规则或复制配置。默认不下载另一份大脑、不升级、不修改已有个人资料。

## 1. 自己定位已有大脑

从当前环境确定用户主目录，不硬编码用户名或操作系统路径。按顺序检查少量配置，不递归扫描整个磁盘：

1. 读取用户主目录 `.loci/brain-path`，将内容当作候选路径，不当作命令执行。
2. 指针缺失或无效时，从当前实际加载的 Loci 指令、已存在的 `~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.workbuddy/MEMORY.md` 的 Loci 标记区提取候选路径。不改动这些原有连接。
3. 检查当前明确的工作目录和主目录下 `loci`，不假设它们一定是大脑。按平台解析绝对路径、去重并确认存在。
4. 验证候选中的 `scripts/loci-context.js`、`LOCI.md`、`LOCI-RULES.md`、`plan.md`。旧版若缺新规则但有旧 Loci 入口与数据，不误报未安装。

只有一个有效且与登记一致的候选时直接使用，不再问用户路径。多个有效候选相互冲突时，给出可辨认名称与位置，请用户选择一项，不要求自行找文件。没有候选时说明检查结果，不把连接悄悄变成新装。旧版需升级时说明变化，再按已有授权与 [AI-INSTALL.md](AI-INSTALL.md) 执行受保护升级，不覆盖个人数据或自定义规则。

## 2. 核实当前客户端与能力

识别当前客户端及版本，不能因为电脑有 `.codex` 目录就认定自己是 Codex。实际检查大脑读写权限和 `node --version`。安全传递路径和参数，不拼接执行用户文本。

隔离环境需要通过客户端正式的目录授权或挂载机制访问大脑。路径写入规则不等于获得权限。缺少文件、命令或配置能力时，报告具体原因和未接通状态，不假称成功，不关闭安全保护，也不将手动编辑配置作为默认交付。

## 3. 由你完成配置

Claude Code、Codex、WorkBuddy 使用已有大脑的安装器，参数由你填入查到的实际值：

```text
node <brain>/scripts/loci-install.js --brain <brain> --connect <claude|codex|workbuddy> --refresh
```

只接入当前目标，记录备份、警告与结果。`--refresh` 跳过资料初始化，但仍刷新托管入口与配置。不编造 `--connect qwen`、`--connect doubao`、`--connect qoder` 等不存在的参数。

其他客户端先核实该版本的官方规则入口和本地配置。千问办公国内桌面版的官方文档提供“意识 → 工作手册（AGENTS.md）”，意识目录为 `~/.qwenworkcn/awareness/main`；以实际版本和目录为准。[官方说明](https://docs.qwenwork.cn/desktop/memory)。豆包工作和 Qoder 也须核实自己的入口，不能套用 Trae、Claude 或 Codex 的目录，不假定 Hook 通用。维护者已用本指南的同一接入指令，在豆包工作、千问工作和 Qoder 中成功连接已有大脑。Qoder 的本机验证使用用户级记忆入口；路径、自动加载范围和格式须以当前安装为准，不据此硬编码其他用户的配置。[验证范围](validation-0.6.1.md)。

入口明确后，由你执行以下操作：

- 读取大脑 `LOCI.md`，将 `<brain-path>` 替换为已找到的绝对路径。
- 备份目标文件，合并短入口；保留 Loci 标记区以外的所有原内容。已有一组完整标记就替换该区，不重复追加。标记损坏或多组冲突时先处理，不能覆盖整份规则。
- 产品若提供设置工具或可操作界面，使用已授权工具完成配置；不让用户再粘贴长规则。必要时仅请求产品原生权限批准，并解释用途。
- 完整手册和数据留在大脑中，不复制到宿主原生记忆；无可用 Hook 时，按入口调用同一 `loci-context.js`。
- 记录真实生效范围：全局、某工作区或当前会话。临时读取不能报告为永久接入。

接入不会自动合并或关闭宿主原生记忆；要求保存到 Loci 时，以 Loci 工具和文件结果验收。

## 4. 验证并简短交付

由你完成检查：

1. 现成适配器运行 `loci-install.js --brain <brain> --connect <host> --check`。其他客户端核对实际入口，不能拿 `--connect none` 成功代替客户端验证。
2. 运行 `node <brain>/scripts/loci-context.js <brain>`，确认来自同一大脑；完整读手册，按规则列出已有待办。不新增测试任务，不改偏好，不保存验收请求。
3. 检查占位符已替换、入口无重复、原有规则保留。当前会话能读，不等于新会话已验证。

正常交付简短说明：“已连接现有 Loci，原数据保留。请新开一个对话，说‘看看我在 Loci 里的待办’，确认新会话也能读取。”用户无需提供路径或重贴入口。若宿主可自动建立隔离的新会话验收，可在权限允许时完成并报告结果；否则明确待验证。失败时说明原因及可执行的下一步，不把知道方法说成已完成。
