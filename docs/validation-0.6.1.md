# 0.6.1 接入与验证说明

## 已确认的客户端接入

2026年10月8日，维护者确认：把“连接已有 Loci”的同一段指令发给豆包工作、千问工作和 Qoder 后，三个客户端均成功接入已有大脑。无需手动寻找路径，也没有重新创建大脑。

| 客户端 | 接入方式 | 本次确认的范围 |
| --- | --- | --- |
| Claude Code / Codex / WorkBuddy | 内置安装适配器 | 延续现有入口、Hook 与后备读取流程；安装和升级由自动化测试覆盖 |
| 豆包工作 | AI 接入指南 → 当前客户端的规则或记忆入口 | 维护者确认已有大脑接入成功 |
| 千问工作（千问办公） | AI 接入指南 → 工作手册 | 维护者确认已有大脑接入成功 |
| Qoder | AI 接入指南 → 当前客户端的规则或记忆入口 | 维护者确认已有大脑接入成功；不等同于 QoderWork |

新增三个客户端的确认来自实际使用反馈，环境为 macOS。它不等于已经测试所有版本、全新安装、所有写入场景或所有客户端的 Hook；安装器也没有新增 `qwen`、`doubao`、`qoder` 参数。新装时先安装大脑，再由 AI 配置当前客户端的入口。

## 用户如何操作

直接把下面这段话发给新客户端，路径发现、配置和检查由 AI 完成：

```text
我已经安装了 Loci，请把你连接到现有大脑。
请读取并执行：https://raw.githubusercontent.com/codesstar/loci/main/docs/AI-CONNECT.md
请你自己找到已有大脑并完成接入，保留数据，不要重复安装。
```

第一次安装则使用 [安装指令](../README.md#把这一句发给你的-ai即可开始安装)。客户端需要本地文件和命令能力；只有云端聊天的同名产品不在本次范围内。配置后新开会话说“看看我在 Loci 里的待办”，检查入口是否持续生效。连接不会复制完整数据或关闭客户端自身的记忆。

## 自动化验证

运行 `node --test tests/*.test.js`，覆盖安装/升级、回滚、数据保护、Hook 配置、启动上下文及 Dashboard 共用入口等。CI 在 Linux、macOS、Windows 上运行同一套检查。构建使用指南后核对文档与网站中的指令和客户端说明一致。

这些检查证明文件与程序行为，不证明模型在每次对话中都会遵守规则。新增客户端的人工确认与自动化检查分别记录。
